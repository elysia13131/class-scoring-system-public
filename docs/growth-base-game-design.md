# 「星辉山谷」成长基地 游戏设计文档

> 版本 v0.1（草案）
> 目标形态：类《部落冲突》的「放置经营 + 轻塔防」，作为现有平台的「成长可视化 + 活跃度引擎」。

---

## 1. 定位与目标

**一句话**：把学员的「真实成长」变成一座可经营、可防守的基地，用明亮好看的休闲游戏审美承载，解决「学员使用积极度低」、让成长「看得见、玩得起来、有迹可循」。

**它不是**：一个独立的纯游戏；**它是**：现有六维评分/体测/学业/打卡数据的「成长可视化层 + 反哺引擎」。落地形态为**独立原生安卓游戏 App**（Godot 4），与主平台共享同一后端（见 §16.0），不占主平台空间。

> **定位铁律（平台主旨不可忘）**：游戏终究是**可视化表现形式**，六维成长与真实进步才是平台主旨。游戏的存在只有一个目的——**把"该补的短板、该做的真事"变得可见、可点击、可坚持**，进而反向推动学员回到真实生活里行动。游戏是"镜子"和"引擎"，永远不是"终点"。判断任何功能该不该加，标准只有一条：**它是否让学员在真实世界里多行动了一步？**

三条不改的底线：
1. 六维雷达图仍是平台主体，基地是其「游戏化镜像」，二者并置。
2. 一切游戏资源只来自**可验证的真实行为**，绝无挂机/点击刷分。
3. 视觉**不贴合军队**，走精致扁平插画的休闲游戏审美（低饱和柔和配色 + 暖金光影 + 细腻渐变，治愈但不低幼）。

---

## 2. 世界观与视觉基调

- 学员 = 一颗「成长星」，坐落在一片「星辉山谷」。
- 六维 = 六类「光之建筑」，用「星辉」（核心资源）浇灌升级。
- 困难与短板 = 周期性来袭的「阴影兽」，用建筑的光去抵御。

**视觉关键词**：精致扁平插画、低饱和柔和配色、暖金色光影、细腻渐变与层次、圆角、无文字越多越好、无武器无血腥、治愈但不低幼。整体贴合 Golden Time 暖色调（金棕 #b8862a / 奶油 #f5e8c8 / 暖白 #faf7f0）作为底色基调，六建筑主色在此底上做**降饱和**处理。UI 用「柔和光晕 + 圆角 + 细腻渐变」营造成长/收集的愉悦感。

## 3. 核心循环（The Loop）

```
真实生活行动 → 结算为「星辉 + 建筑经验」
       ↓
    建造 / 升级建筑（经营面）
       ↓
    抵御「阴影兽」波次（塔防面）
       ↓
    变强 / 补短板 → 提示下一步行动 → 回到真实生活
```

关键：**游戏的每一次"变强"都必须对应一次真实世界里的行动**，不能凭空发生。

### 3.1 「结算层」与「游玩层」分离（核心修正）

真实行为不是每时每刻都有的——学员不可能天天有体测、竞赛、带队任务。若游戏循环把"能不能玩"绑定在"今天有没有真实行为"上，就会在行为空白日（工作日未开训、周末、假期、复习周）变成一潭死水。因此必须把两类东西拆开：

| 层 | 决定什么 | 触发前提 | 是否随时可玩 |
|---|---|---|---|
| **结算层**（星辉/经验入账） | 你能获得多少成长值 | 必须有真实行为凭证 | 否（有行为才结算） |
| **游玩层**（建造/布置/防守/参观/规划/社交） | 你现在能不能玩 | 无 | **是** |

**含义**：真实行为只决定"入账"，不决定"能不能玩"。基地经营、防御布阵、回看防守、装饰基地、参观同学基地、AI 教练共订目标、规划升级路线——这些**随时可玩、无需等待行为**。行为结算只是"给游玩层注入新的资源"，而不是"游玩的开关"。

### 3.2 「每日保底」：复用已有的日活功能，不新造名词

保证"每天至少有一次真实结算"，**不该新造一套微行动**，而是把平台上已有的日活功能直接纳入结算层：

| 已有功能 | 真实含义 | 绑定维度 | 结算依据 |
|---|---|---|---|
| **每日一问**（`/checkin/student-question`） | AI 生成个性化反思问题，学员回答 | 素养/文化馆 | 有回答记录即入账 |
| **速记打卡**（`/checkin/feedback`） | 记录心情 + 标签 + 文字 | 素养/文化馆 | 主动记录即入账 |
| **日程**（`/api/schedules`） | 创建/完成个人日程 | 管理/领航台 | 日程被勾选为"已完成" |

这三者本就是平台已有的、每天都会触达学员的入口。它们单次星辉低（+2~+8），搭配**每日首次加成**与**连续 N 天加成**，自然形成"每天都有一次真实行动→游戏有回应"的肌肉记忆，无需再造"整理内务/早起打卡"这类与现有功能重复的东西。

**原则**：能复用已有功能就不新造；新造必须是已有功能覆盖不到、且确有价值的真实行为（如委托、擂台）。

### 3.3 「蓄能值」：给回流动力，但不违反"不挂机变强"

- 离线期间，基地缓慢累积一条**蓄能值**（有上限，如 48h 封顶）。
- 蓄能值**本身不是成长值**，无法直接兑换成星辉/经验。
- 它的作用：下一次**真实行为结算时**，作为"倍率/加成"释放（例：蓄满时本次结算 ×1.5，但消耗掉蓄能）。
- 效果：既让"几天没来"的学员有回来的理由，又守住底线——**不做事，点数永远不发**。蓄能只是"攒了个加速器"，还得靠真实行动点火。

### 3.4 AI 教练把"空白日"变成"规划日"

没有大事件的日子，游玩层的重点是**共订目标**：AI 教练基于当期短板，把"下一步成长"拆成**本周可随时推进的小目标清单**（而非等体测/竞赛）。空白日的游玩价值 = 规划 + 布置 + 参观 + 社交，确保"没事做"不等于"没得玩"。

## 4. 六维 ↔ 六建筑映射

| 维度 | 建筑 | 视觉意象（非军事） | 主色 |
|---|---|---|---|
| 体能 | 训练场 | 活力健身房、跑道、哑铃、沙袋 | 橙黄 |
| 学业 | 学习塔 | 魔法图书馆高塔、漂浮发光书、猫头鹰 | 蓝紫 |

## 5. 资源系统

| 资源 | 含义 | 来源 | 用途 |
|---|---|---|---|
| 星辉 | 通用成长值（唯一硬通货） | 仅真实行为结算 | 建造、升级、解锁 |
| 建筑经验 | 单维度经验 | 该维度真实行为 | 对应建筑升级 |
| 声望 | 社交货币 | 被感谢、帮带 | 荣誉墙、兑换（见 §9） |

**设计要点**：星辉不随放置时间被动产出（防止「挂机就变强」）。放置产出只能给「装饰/皮肤碎片」等轻量展示物，绝不产出成长数值。

## 6. 真实 ↔ 游戏 的联动（核心，需重点把控）

### 6.1 四大原则
1. **闭环凭证**：每笔资源入账都有可验证凭证（委托的对方确认、体测成绩、打卡记录、竞赛证书审核、任务完成）。
2. **同源不同轨**：六维评分（别人怎么看，软性、会饱和）与基地成长（自己做了什么，硬性、累积）平行存在、互不兑换、互为参考。基地不读评分、评分不读基地。
3. **上限 + 衰减**：每类行为设每日/每周上限，防爆肝；同类行为单日内重复做，资源按 `100% → 50% → 25% → …` 衰减。
4. **失败不羞辱**：塔防守不住只给「建议行动」，不给惩罚。

### 6.2 行为 → 资源 映射表（初稿，系数可调）

| 真实行为 | 建筑/维度 | 星辉 | 建筑经验 | 凭证（T 级，见 §11.2） |
|---|---|---|---:|---:|---|
| 体测项目及格 | 训练场 | +20 | +20 | T1 体测成绩记录 |
| 体测项目较上次进步 | 训练场 | +30 | +30 | T1 同比进步 |
| 每日一问回答（`student-question`） | 文化馆 | +5~8 | +5~8 | T1 回答记录 |
| 速记打卡（`/feedback`） | 文化馆 | +5 | +5 | T1 心情/标签/文字记录 |
| 日程按时完成（`/schedules`） | **按日程目标维度归属**（v0.2 修正：由 AI 教练在生成日程时指定，如"3 次夜跑补 3000 米"→ 体能；未指定默认领航台） | +8 | +8 | T1 日程标记完成记录 |
| 完成 1 次互助委托（待建） | 互助驿站 | +15 | +15 | T2 发布者确认 |
| 完成 1 次成长(目标)委托（待建） | 对应维度 | +25 | +25 | T2 目标达成+自证 |
| 擂台对战（见 §7.2，**不产星辉**） | — | 0 | 0 | 切磋分 + 声望，独立存 `arena_*.json` |
| 竞赛/证书/获奖 | 对应维度 | +50 | +50 | T3 AI 初审 + 公示质疑 |
| 值日/公差按时完成 | 秩序哨站 | +8 | +8 | T1 任务完成记录 |
| 连续纪律打卡 7 天 | 秩序哨站 | +40 | +40 | T1 连续记录 |
| 带队/任职表现 | 领航台 | +30 | +30 | T3 骨干评价 |

- **每日星辉总上限**：默认 200（可由管理员配置）。
- **大事件脱钩日上限（v0.2 修正，F1）**：体测进步/考试成绩提升/证书获奖等锚点级大事件单独结算（+60~100），不受每日 200 上限挤压——真实大事件必须是"暴击时刻"，不能被日常小额淹没。
- **衰减规则**：同类可重复行为（如打卡）单日内第 1 次 100%，第 2 次 50%，之后 25% 封顶。

### 6.3 这是「成长」不是「刷分」的关键
因为资源只随**真实事件**累积、且有上限衰减，所以：
- 想变强，只能真的去练、去学、去帮人；
- 游戏数值天然「反内卷」——刷不了，只能踏实成长。

### 6.4 反哺闭环：游戏如何"推着学员回到真实生活"

游戏如果只读数据、只给奖励，就会沦为另一块屏幕里的消遣。**它的真正价值是从游戏反向驱动真实进步**。反哺闭环设计如下：

```
[游戏读取真实短板] → [映射为"下一步行动"建议] → [学员一键认领成委托/打卡/目标]
        ↑                                                              ↓
[结算后游戏变强，又暴露新短板] ← [双方确认/自证，真实行为完成] ← [学员回到真实生活执行]
```

四个反哺抓手：

1. **建议即任务**：塔防守不住、短板暴露时，弹出的"建议行动"不是一句空话，而是一键**生成真实委托/打卡/目标**（例：AI 生成"本周陪你练 3 次仰卧起坐"→ 生成一条互助委托 → 挂到委托大厅 → 有同学接单）。**从"看到短板"到"行动落地"最多 2 次点击。**
2. **缺口导向的周任务**：AI 教练每周按"真实数据缺口"（哪一维多久没记录了）生成一份「本周小目标清单」，落到游戏里成为可勾选的任务卡。游戏的任务列表，本质是"真实行动待办清单"。
3. **反哺型权益**：权益兑换（§9）不做成"回馈性奖励"（花星辉买东西），而是做成"**前置型推动**"——例如"花星辉开启一次 1 对 1 补短板委托"，花的是星辉，换来的是"别人带我做一次真事"。钱花出去，真实行动被拉进来。
4. **社交互推**：擂台（§7.2）是"用六建筑互相攻防"，胜负只产切磋分与声望、不产星辉；赢的人拿到"帮带权"去带落后同学——**游戏的胜负直接转化为真实世界里的带动关系**。

**主旨校验**：游戏里每一次"变强"都追问一句——它是不是让学员在真实生活里多走了一步？若是，保留；若只是让他在游戏里多点了两下，砍掉。

### 6.5 平台不可替代性（回答"学员凭什么用这个平台"）

必须承认三个现实弱点，承认它们是设计前提而非逃避：

1. **平台没有社交信用度**——学员之间交流用微信，不欠平台一个对话入口。
2. **现实委托吸引力弱**——同班同学线下/微信一句话就能求助，不会专程登录 App 发委托。
3. **内容型方案没有护城河**——高光视频、回顾、成长故事别人做得更好看，跟短视频平台抢注意力必输。

上一版方案（内容工厂/LBS/实体化）被否的原因：它们仍在"把数据展示得更好看"，而**好看从来不是护城河**。真正的护城河是**场景独占**：只有这个平台同时拥有——**一个真实的班级组织 + 全员成长数据 + 公正结算账本**。

由此导出生存之道：**虚拟机制治理现实班级，现实活动反哺虚拟世界**。一句话：**让"星辉"在班里能办事。**

| 旗舰能力 | 虚实咬合点 | 为什么别人拿不走 |
|---|---|---|
| **星辉拍卖行** | 虚拟货币 → 现实班内权益 | 只有这里能"公正计价 + 公示 + 不赖账" |
| **班级攻防战** | 现实班级 = 游戏阵营 | 只有这里有全班数据 + 中立记分牌 |
| **现实事件副本** | 现实活动 → 限时游戏事件 | 只有这里能把现实活动写进班级编年史 |

**旗舰能力一：星辉拍卖行（游戏的钱，在班里花得出去）**

每周一场班内拍卖，拍品是**真实权益**，星辉即货币：

- **值日任务包**（轻松岗/自由选岗/和人一组）；
- **活动决策票**（下周班会内容、集体活动选项的加权票）；
- **点名表扬位**（周二晚点名的"本周之星"展示位）；
- **班务选择权**（值日顺序自选、座位调换权）。

为什么这比"奖励列表"强：奖励是平台给的，而拍卖是**学员用自己挣的星辉"买"现实结果**——钱的流通感、竞价的刺激、赢得时的真实兑现，构成每周一次的班级事件。平台的角色是**唯一公正账本**：定价、公示、结算、兑现全程留痕，谁也不会赖账、谁也不能插队（管理员只配拍品与额度）。

**旗舰能力二：班级攻防战（现实班级就是游戏阵营）**

`members.json` 的 `class` 字段直接成为游戏阵营。每周跨班基地攻防：

- 全班基地聚合为"班级领地"，班级之间互攻（市长=班长或骨干，成员贡献建筑与卡牌）。
- **胜负挂钩现实**：赢班全员获得拍卖行专属拍品（如"下周一响铃前免集合点名一次"）。
- 现实中的班级荣誉感（拔河、球赛全班呐喊）从未有中立记录者——平台是唯一的**记分牌 + 战报档案**，战败也有复盘、战胜全班留名。

**旗舰能力三：现实事件副本（现实活动自动变游戏事件）**

不另造活动，而是**贴着现实日历走**：体测周解锁"训练场应急周"副本、考试周开"学习塔冲刺波"、运动会开全服 Boss——现实发生什么，游戏就同步什么，活动结束自动生成**班级编年史条目**（某年某月，班级在运动会 Boss 战全员存活记录）。让游戏成为班级现实的"编年史官"。

**委托的重新定位（关键修正，保留）**：
不跟微信抢"即时求助"，而是做**线下见证**——低门槛双轨：

- **线上委托**（保留）：需要 AI 撮合/跨班求助的才走线上（跨班不熟的人之间）。
- **线下见证补录**（主推）：学员线下已经帮了人（带练/讲题/帮忙），事后回 App **补录一笔**「今天帮某某做了 X」，对方点确认。**不需要改变用户已有行为**，平台只做"记账 + 展示 + 换算成荣誉"。

这一下把委托的使用门槛从"来平台求助"降到"顺手记一笔"，补录同样产星辉/声望（额度受限、凭证 T2）。善意从此有迹可循、有榜可上——这是微信永远给不了的。

**长期吸引力钩子（班级事件节奏）**：

| 时间 | 钩子 |
|---|---|
| 每周 | 星辉拍卖会 + 班级攻防战 |
| 每月 | 现实事件副本（贴现实日历）+ 月度编年史 |
| 每学期 | 学期班级荣誉结算 + 勋章实物发放 |
| 毕业/结业 | 个人成长档案 + 班级编年史实体册——终局奖励 |

> 核心信念：**别的 App 给你内容和消费；这个平台用一套公正账本，让你的努力在现实班级里换成真实的权利和荣誉。**"星辉能办事"才是无法被替代的吸引力。

## 7. 战斗系统：塔防波次 + 擂台攻防

游戏有两条战斗线，共用同一套「六建筑」作为战力来源：

| 战斗线 | 对手 | 本质 | 奖励 |
|---|---|---|---|
| **塔防波次（PvE）** | 阴影兽（真实短板投影） | 体检报告，补短板 | 星辉 + 荣誉 |
| **擂台攻防（PvP）** | 其他学员的基地 | 设施对抗，证明成长 | 切磋分 + 声望 |

两条线的共同点：**战力都来自六建筑等级，而等级来自真实行为**——战斗强 = 成长扎实，无法靠点击刷出来。

### 7.1 塔防波次（PvE：短板可视化）

- **阴影兽 = 真实短板/压力的投影**，映射到六维。
- **波次难度由真实短板动态生成**：某维度长期（≥3 周）无成长记录，或体测/学业出现明确弱项，对应「阴影兽」在该周副本显著变强。
- **防守结算**：守住 → 星辉 + 周荣誉 + 稀有掉落；守不住 → 不惩罚，仅生成一条「建议行动」（例：「你已 3 周没有体能类成长记录，建议本周完成 1 次体测加练委托」）。
- **效果**：游戏难度即体检报告，**"玩"就是在补短板**。

**轻量化形态**：不做实时 RTS，做成「放置型防御波次」——登录后布置/升级建筑，看自动防守结算。周为「战略周期」：每日小额波次 + 周末 Boss 波。

**光值注入（v0.2 修正，F2 —— 反哺即时化）**：任何绑定该维度的真实行为完成结算时，**当场**向对应阴影兽注入光值（带可视化削弱动画），波次强度 = 阴影兽**当前残余强度**（而非周初快照）。效果：① 因果即时可见——"我做了 X，兽当场变弱"；② 塔防从"周体检"升级为持续的光暗拉锯；③ 与日程维度归属修正（F1）协同，任何维度任何行为都在打自己的兽。

### 7.2 擂台攻防（PvP：COC 式设施对抗）★ 核心玩法

把「经营面」搭好的基地，变成可互相攻伐的战场——**用已有设施彼此对抗**。

#### 战斗单位：六建筑一物两用

六建筑既是「防御工事」，也是「进攻部队的合成来源」，无需额外造兵。每座建筑有战斗定位：

| 建筑 | 攻防定位 | 说明 |
|---|---|---|
| 训练场 | 高血量·前排 | 撑血量，挡伤害 |
| 学习塔 | 高输出·点杀 | 单体高伤，打关键目标 |
| 秩序哨站 | 控制·减速 | 拖慢敌人节奏 |
| 互助驿站 | 治疗·增益 | 给友方回血/加 buff |
| 领航台 | 统帅·光环 | 提升全场攻防 |
| 文化馆 | 范围·AOE | 群体伤害 |

每建筑 `战力 = 等级 × 该维度近 4 周活跃度`（§11），战力高低全看真实行动。

#### 防守：布阵
- 学员在基地网格上**自由摆放六建筑**，形成防守阵型（前排肉盾、后排输出），有真实策略空间。
- 布阵直接决定被攻打时的胜负——像 COC 的阵型设计，可保存多套阵型应对不同对手。

#### 进攻：出击
- 消耗**「出击令」**（每日免费 3 次，不消耗星辉），选择同段位对手发起进攻。
- 己方**「星芒」**（成长之光凝聚的进攻单位）由六建筑等级合成，数量与强度随成长提升。
- 放置星芒 → 自动寻路攻打对方建筑 → 按摧毁比例定星级：≥50% 得 1 星、≥70% 得 2 星、全歼得 3 星。

#### 克制环（策略深度）
六维构成克制关系，进攻选克制对方强势建筑的星芒、防守保护自身弱点，增加战术考量：

```
体能 → 纪律 → 学业 → 管理 → 素养 → 贡献 → 体能（循环）
```

#### 结算与防刷（关键：避免假赛刷分）
- **胜负不产星辉/建筑经验**（否则假赛刷成长），只产：
  - **切磋分**（Elo）：决定段位与排名，输赢浮动。
  - **声望**（小额）：被挑战/匹配到，体现"社交认可"。
- **失败不羞辱**：只给"防守复盘建议"。
- 每日出击封顶 3 次，防沉迷。

#### 真实联动（回到主旨）
- 防守中被攻破的建筑 = **该维度短板暴露** → AI 生成"本周补强建议" → 一键落成日程/委托。
- 进攻连胜 = 该维度成长扎实 → 解锁"帮带权"（带落后同学，产声望）。
- 擂台胜负**不写回 `scores.json`**，独立存 `arena_*.json`，不污染评分主体。

#### 社交与赛季
- 周擂台榜 + 赛季段位（结合学期，见 §12 永恒层/赛季层）。
- 战报可回放：看到自己基地如何被攻破，激发"下次改进阵型"的正反馈——这才是真游戏的正循环。

### 7.3 卡牌系统（光之刻印）★ 可玩性核心

给经营 + 塔防 + 擂台加一层"构筑型卡牌"，像《皇室战争》的卡组与《三幻》的图鉴——**收集、构筑、交换**三件事本身就是可玩内容。

#### 卡牌来源：真实行为掉落，绝不氪金
- 完成任何真实行为（打卡/日常/委托/擂台/塔防）→ 掉**卡包**；达成里程碑 → 掉**金卡包**。
- 不存在付费购买通道。**卡强不强 = 行为多不多**，与"成长"同源。
- 上限防爆肝：每日掉卡包数封顶（如 5 包）。

#### 卡牌类型（三大类）

| 类型 | 作用 | 例子 |
|---|---|---|
| **建筑增益卡** | 插到建筑槽上，改变建筑攻防行为 | 「治愈光环」给互助驿站 + 范围治疗；「棱镜」让文化馆 AOE 分裂 |
| **技能卡** | 波次/对战中手动释放 | 「光盾」挡一次 Boss 攻击；「回溯」重放上一秒战局 |
| **纪念卡** | 纯收集，进图鉴 | 「流星之夜」赛季纪念；「第一次 3 星」里程碑卡 |

#### 卡组构筑（策略深度）
- 塔防/擂台开战前，从收藏中**出战最多 4 张**（1 建筑增益 + 3 技能），构成卡组。
- 卡组与建筑等级、布阵、克制环叠加出策略空间：同样的基地、不同的卡组 = 不同的打法。
- 图鉴完成度给**收集者奖励**（限定皮肤/称号），接住后期饱和（§12）。

#### 交换与炫耀
- 同班学员间可 1 换 1 **交换纪念卡**（必需不同稀有度防刷）。
- 图鉴秀可以挂在基地里供参观——社交炫耀驱动收集。

### 7.4 放松性设计（游戏不是另一个任务）

主旨不是把学习变成游戏，而是**让游戏本身成立**——放松是第一性的，"顺带看见成长"是第二性的。

| 设计 | 内容 |
|---|---|
| **收菜仪式** | 每日登录有可收的资源/掉落/足迹，不登录也无损失（只错过，不惩罚） |
| **装饰沙盒** | 摆建筑、铺小路、挂彩灯，纯装饰无收益，但对"自己的山谷"有占有感 |
| **拜访彩蛋** | 参观同学基地可发现随机的"山谷彩蛋"（收集品/笑话/天气变化），无负担 |
| **零挫败** | 塔防/擂台失败从不扣资源、无红字羞辱，只有"给你个想法"的轻提示 |
| **无强制打卡感** | 所有"必须做"的任务只有真实行为的自然映射，游戏内不含指标压力 |

一句话：**玩家留下来的第一原因必须是"这里好看、好玩、待着舒服"，成长是随之发生的事。**

## 9. 奖励体系（玩本身就该有甜头）

奖励的设计前提：**玩家首先是来放松的，不是来上班的**。奖励分三轨——"游戏内爽感"即时可见，"现实小确幸"真实可感，"权力轨"让星辉在班里办成事（§6.5 旗舰能力一）。

### 9.1 爽感轨（游戏内，零成本即时发放）

| 奖励 | 触发 | 性质 |
|---|---|---|
| 建筑皮肤 / 基地主题（季节限定） | 段位/成就/活动 | 收集欲 + 炫耀欲 |
| 星芒外观（彩虹尾迹、流星特效） | 抽卡掉落 / 赛季奖励 | 个性化 |
| 称号与段位特效（进榜播报） | 擂台/塔防成绩 | 荣誉感 |
| 基地拜访足迹 / 纪念雕像 | 里程碑 | 沉淀感 |

这些奖励**不存在额度问题**，可以大方给——它们是游戏"好玩"的底气。

### 9.2 权力轨（星辉拍卖行：游戏的钱在班里花得出去）★ 核心

每周一场班内拍卖，用星辉竞拍**真实班内权益**（§6.5）：

| 拍品 | 示例底价 |
|---|---|
| 值日任务包（轻松岗/自由选岗） | 600 星辉 |
| 活动决策票（班会内容加权票 ×1） | 800 |
| 点名表扬位（本周之星展示位） | 1000 |
| 班务选择权（值日顺序自选） | 500 |

- 平台是**唯一公正账本**：定价/公示/结算/兑现全程留痕，不赖账、不插队。
- 管理员只配置拍品与额度；拍卖结果自动生成凭证，兑现点一下就完成。
- **拍品分两类（v0.2 修正，F3 —— 星辉流向承接方，杜绝零和再分配）**：
  - **平台权益类**（活动决策票、表扬位、班会内容）：星辉沉淀为 sink，合理；
  - **劳动交换类**（免值日、轻松岗、值日顺序）：**买方支付的星辉全额流向承接方**——A 花 500 买"免值日"→ 替班的 B 获得 500 星辉。语义与委托系统统一："帮人干活 = 挣星辉"，星辉成为班内劳动的记账单位并在班内循环，而非蒸发。这消除"星辉有钱 = 能买同学劳动"的零和矛盾，也是 L4 货币联动的完全体。
- **这是"奖励实际意义"的最强形式**：不是平台发奖品，而是学员用自己挣来的钱买现实结果——流通感 + 竞价刺激 + 真实兑现，每周一次班级事件。

### 9.3 放松轨（现实小确幸，管理员可配置额度）

用星辉/声望兑换**真正让人想放松的东西**，兑换后由系统自动生成凭证、管理员点一下就能兑现：

- 🧋 **奶茶/零食券**：一次集体零食拼单由平台方代订；（示例：800 星辉）
- 🎬 **观影/娱乐名额**：本周班级观影/桌游/球赛名额优先；（示例：1500）
- 🎵 **点歌权**：晚餐/课间广播点一首歌；（示例：300）
- 🌙 **免值日一次**：最朴实但最抢手的硬通货；（示例：500）

> 额度与价格由管理员后台逐项配置；兑换记录进 `game_ledger.json` 审计。**原则：奖励要让学生"想要"，而不是"应该要"**——想要才驱动行动，应该要只会变成任务。

### 9.4 反哺型权益（花资源换"被带一次"）

星辉也能花在"让别人带我做一次真事"上：开启 1 对 1 补短板委托。钱花出去，真实行动被拉进来——这是唯一"不放松"的奖励，因为它是**自己主动买的**。

## 11. 数值框架与成长节奏（核心，解决"真空期/刷分/贫富分化"三问）

基础曲线：
- 建筑升级消耗：`升级消耗(i) = base × 1.8^(i-1)`（初稿，具体每建筑可不同）。
- 段位按「累计星辉」：`星尘 → 星芽 → 星火 → 星辉领主`（名字可再定）。
- 塔防中每建筑 `防守值 = 等级 × 该维度近 4 周事实成长活跃度`（活跃度=有行为记录的周数占比），保证「最近真正在练的人更强」。

### 11.1 短周期成长快感：把"低频大事件"拆成"高频小反馈"

**现实问题**：考试/体测/证书一个月甚至一学期才更新一次；如果建筑经验只靠它们，学员绝大多数字子里感受不到成长，游戏就凉了。

对策一：**快感颗粒度下移**——经验条每天都动
- 每日保底行为（每日一问/速记/日程/委托，§3.2）给小额经验（+2~8），让六根经验条**天天有进度**。
- 升级曲线**前快后慢**：Lv1→2 只需 3~4 次微行为（新手第一周连升 3 级，体验"成长起飞"）；Lv8→10 放慢，对应真实成长的平台期，**不造假、不注水**。

对策二：**卡包是短周期正反馈主力**
- 真实行为掉卡包（每日 ≤5 包）+ 开包动画（§7.3）。收集 + 随机 + 可构筑，构成一个 2 分钟一个的爽感闭环，完全不受低频数据制约。

对策三：**低频事件做成"暴击时刻"**
- 体测/考试/证书结算日 = 盛典时刻：升级动画 + 班级播报"XX 的学业塔突破 Lv7"。
- 把"稀疏"变成"期待"——大日子有大仪式，小日子有小甜头。

### 11.2 凭证分级：让刷分无利可图

**现实问题**：`scores.json` 已是「同源不同轨」不进游戏，但 `experiences.json`（经历/证书）等**自报型数据**容易乱填刷分。

对策：按**凭证可信度分级**，信任等级决定结算方式：

| 凭证等级 | 来源 | 结算方式 | 例子 |
|---|---|---|---|
| **T1 系统记录** | 平台自动产生 | 即时入账 | 体测/学业/排名/打卡数据 |
| **T2 双方确认** | 需他人确认 | 确认后才入账 | 委托完成（发布者确认） |
| **T3 AI 初审 + 社会监督** | AI 验证 + 公示质疑 | 初审通过即入账，公示期可质疑冻结 | 证书/获奖/经历自报 |

T3 审核可以放心交给 AI + 公示组合，管理员只做兜底：
- **AI 初审**：OCR 识别证书/奖状文字、与已有数据**交叉验证**（例：自称"排名第一"但 `rank_scores.json` 无记录 → 标记存疑）、时间与逻辑矛盾检测。
- **管理员抽检**：只处理 AI 存疑项 + 随机抽检（约 5%），负担从"全量审核"降到"例外处理"。
- **公示质疑**：入账后 48 小时公示，同班可匿名质疑；被质疑即冻结转人工复核。社会监督补上 AI 漏判。
- 一个关键优点：AI 审核**没有"人情分"**——管理员可能碍于情面放行，AI 不会。

规则：
- **大额奖励（≥ +20）必须 T2 或 T3**——自报永远拿不到大额，刷分的投入产出比直接归零。
- **账本透明**：每笔入账在 `game_ledger.json` 可追溯凭证，同学可见——刷分等于公开丢人。

### 11.3 防贫富分化：让差距"追得上"，而不是"锁死"

**现实问题**：先玩/贡献多的学员数据厚、建筑高，容易赢者通吃，新人躺平。

对策：
1. **每日上限**（默认 200 星辉）——任何人一天最多拉开 200 的差距，勤奋不能一夜登顶。
2. **衰减曲线**（100%→50%→25%）——边际递减，"刷得多"不如"每天做对的事"，抑制内卷。
3. **活跃度权重**（§11 基础公式）——躺平的老玩家防守值自动衰减，防"吃老本永久压制"。
4. **同段位匹配**——擂台只和同水平的人打（§7.2），实力悬殊者互不碾压。
5. **周榜为主、总榜为辅**——当期表现人人有机会上顶；历史积累只进荣誉墙/成长内容流。
6. **短板加速**：落在"落后维度"的建议行动奖励 +20%——补弱比刷强更划算，差距自然收敛。
7. **正和互动**：委托/帮带让强者带弱者**双方都得利**——贫富之间是输送，不是零和。

## 12. 后期反饱和设计（成长不是无限线性）

你已点明关键：**六维评分在长期后会趋于稳定，进步进入平台期**。若游戏靠"更高的等级/更大的数字"来留人，必然在学员达到 Lv.10、段位见顶后失速——这正是「大后期饱和」的根源。

反饱和的总纲：**当"长高"到顶，就转向"变宽、变深、变美、变有用"**。数值有顶，故事与影响没有。

### 12.1 四条反饱和路径

| 路径 | 机制 | 解决什么 |
|---|---|---|
| **横向专精** | 建筑满级后解锁该维度 3 个「专精分支」（例：训练场满级 → 耐力 / 爆发 / 柔韧），单线变多线 | 纵向数值封顶后的新增长空间 |
| **身份跃迁** | 段位见顶后进入「传承」身份：从"被培养者"转为"培养者"，解锁带新、带练、评审、答疑等玩法，产出「声望」而非星辉 | 数值到顶后仍有新目标、新价值 |
| **收藏与叙事** | 皮肤/装饰/纪念徽章/「班级编年史 + 个人纪念册」，靠时间沉淀，不靠数值 | 把"到顶"转成"故事继续" |
| **赛季重置 + 永恒层** | 赛季段位/排名每季重开（给新鲜目标），但建筑等级/图鉴/编年史作为**永恒层**永久保留 | 既有"重开的新鲜"，也有"累积的沉淀" |

### 12.2 后期玩家画像与对应钩子

1. **满级强者**：数值无欲无求 → 钩子转向「传承」——带新学员、当评审、解更高难度的集体副本，产出声望与真实权益（见 §9）。
2. **平台期普通学员**：进步不明显、易流失 → 钩子是「编年史 + 拍卖行」——不奖励"分数上升"，而奖励"记录完整 + 参与变现"，让人留下是因为"我的努力在班里换得到真实的东西"，而非"我变强了"。
3. **收集型玩家**：靠徽章/皮肤/限定主题赛季维持新鲜感（见 §10 留存节奏）。

### 12.3 关键原则

- **后期不靠更高数字留人，靠"更丰富的身份 + 叙事 + 影响他人"留人**。
- 星辉、建筑等级只是**前中期**的成长引擎；**声望、传承、拍卖行/班级战**才是**后期**的引擎。
- 永恒层（建筑/图鉴/编年史）永不重置，给"沉淀感"；赛季层（段位/排名）按时重置，给"新鲜感"。两者并存，饱和就不会发生。

## 13. 防刷 / 防变味 清单

- 资源仅来自凭证化真实行为；
- 每日/周上限 + 衰减；
- 放置不产成长数值；
- 塔防失败不羞辱；
- 权益兑换由管理员配置额度；
- 数值不得由结算器《凭空生成》，必须绑定成员真实事件流水；
- **擂台胜负不产星辉/建筑经验**（只产切磋分 + 声望），且每日出击封顶、服务端判定，防假赛刷分；
- **卡牌零付费**：卡包仅真实行为掉落，每日掉包封顶；交换仅限同稀有度 1 换 1，防倒卖刷号；
- **线下见证补录防刷**：`happenedAt` 限回溯 7 天、每日补录条数上限、金额受每日星辉总上限约束，不可囤积。

## 15. 与现有系统的关系（按真实数据文件对齐）

> 游戏不引入平行的"虚拟数据"，而是**直接读取/写入已有真实数据文件**，确保"玩的就是真的"。

| 现有数据文件 / 能力 | 真实含义 | 在游戏中的角色 |
|---|---|---|
| `scores.json`（六维评分） | 别人怎么看（软性，会饱和） | 与基地并置，**不进入游戏数值**，仅作雷达主体 |
| `fitness_scores.json`（体测） | 体测成绩、同比进步、BMI | 训练场经验 + 短板来源（体能弱项 → 阴影兽变强） |

| `duties.json`（值日/公差） | 任务完成记录 | 秩序哨站经验 + 「减免公差」权益的直接数据源 |
| `experiences.json`（经历/证书） | 竞赛/证书/获奖 | 大额星辉 + 对应建筑经验的凭证入口 |
| `weekly_reports.json`（周通报/纪律分） | 每周遵章守纪分（基于 80 基准的累计） | 秩序哨站经验 + 纪律短板来源 |
| `委托 / 擂台 / 卡牌`（**待建**） | 互助、设施攻防、收集构筑 | 反哺闭环载体（§16.3/16.4）+ 可玩性核心（§7.3） |

| `agent`（AI 教练） | 分析、建议、记忆 | 生成「周目标清单」+ 把短板翻译成可执行的委托/任务 |
| `push / pushManager` | 消息推送 | 日结算、波次开始、权益到账、委托被接单提醒 |

**关键**：委托/擂台目前尚未实现，是 M3 里程碑的必做项——它们是"反哺闭环"的落地载体，没有它们，游戏就退化成只读数据的展示板。

### 16.0 客户端架构：独立原生游戏 App（Godot 4）

- **发布**：随主平台版本节奏独立构建 APK，走现有 `/api/apk/*` 更新机制（或单独游戏更新通道）。

### 16.3 委托系统（delegations.json，双轨：线上求助 + 线下见证补录）

```jsonc
{
  "id": "dg_...",
  "mode": "offline",                // "online"（线上求助）| "offline"（线下见证补录，主推）
  "title": "帮你讲了 3 道高数题",
  "dimension": "study",             // 绑定六维：study/fitness/literacy/discipline/contribution/management
  "publisherId": "1001",           // 线上：发布者（求助方）；线下：受助方（被帮助的人）发起补录
  "assigneeId": null,              // 线上：接单者；线下：施助方（帮了忙的人），补录时直接填
  "status": "open",                // open → accepted → done → cancelled；线下补录直接创建为 done 待确认
  "createdAt": "...",
  "happenedAt": "...",              // 线下补录：真实发生时间（可回溯 ≤7 天，防积压刷分）
  "confirmNote": "",               // 对方确认说明（凭证）
  "rewarded": false                // 幂等标记
}
```

接口：
- `POST /api/delegations` —— 发布（线上 mode=online，publisherId 自动 = 当前学员；AI 反哺可代发）。
- `POST /api/delegations/witness` —— **线下见证补录**（mode=offline）：助人方填"帮了谁+做了什么"，生成待对方确认的记录。
- `POST /api/delegations/:id/accept` —— 线上接单（assigneeId = 当前学员，status→accepted）。
- `POST /api/delegations/:id/complete` —— 线上：接单者标记完成（待确认）。
- `POST /api/delegations/:id/confirm` —— **对方确认**（写作 confirmNote，status→done；线上/线下共用）。
- `GET /api/delegations/:memberId` —— 我的委托/见证记录列表。

结算（§16.5）：确认后**双方**各得星辉（施助方 +15 互助驿站、受助方 +15 对应维度）。凭证 = `confirmNote`（T2）。
防刷：线下补录 `happenedAt` 限回溯 7 天内、每日补录条数上限、金额受每日星辉总上限约束——善意可记，不可囤。

### 16.4 擂台攻防（COC 式，三份文件）

擂台不再"比行为数"，而是"用六建筑互相攻防"。需三份新增文件：

**① `arena_layouts.json` —— 基地布阵**（防守方）

```jsonc
// 按 memberId 索引；每成员 1 条
{
  "memberId": "1001",
  "grid": [                         // 6x6 网格上的建筑摆放（防守阵型）
    { "buildingDim": "fitness",  "x": 0, "y": 2 },
    { "buildingDim": "study",    "x": 2, "y": 2 },
    { "buildingDim": "discipline","x": 4, "y": 1 }
    // ...六座各占一格
  ],
  "updatedAt": "beijingISO"
}
```

**② `arena_battles.json` —— 对战记录 + 战报**（可回放）

```jsonc
{
  "id": "ar_...",
  "attackerId": "1001",
  "defenderId": "1002",
  "attackerUnits": [ "fitness", "study", "study" ],  // 出击星芒（由己方建筑等级合成）
  "defenderLayout": { ... },        // 快照：防守方当时的布阵
  "stars": 2,                       // 0~3 星（按摧毁比例判定）
  "destructionPct": 72,
  "destroyedDims": ["discipline","literacy"],   // 被攻破的建筑维度 = 防守方短板暴露点
  "eloDelta": { "attacker": +12, "defender": -12 },
  "createdAt": "beijingISO",
  "replaySeed": "..."               // 战报回放所需确定性随机种子
}
```

**③ `arena_ratings.json` —— 切磋分/段位**

```jsonc
{
  "memberId": "1001",
  "elo": 1320,
  "tier": "星火",                    // 段位（见 §11）
  "seasonId": 4,
  "wins": 8, "losses": 5
}
```

接口：
- `GET/PUT /api/arena/layout/:memberId` —— 查询/保存自己的布阵。
- `POST /api/arena/attack` —— 发起进攻：body `{ attackerId, defenderId, unitDims[] }`。服务端校验出击令剩余 + 同段位匹配，扣出击令，跑确定性的攻防结算，返回战报 + 星级 + Elo 变化。
- `GET /api/arena/battles/:memberId` —— 我的战报列表（可回放）。
- `GET /api/arena/ranking?tier=&seasonId=` —— 擂台榜。

关键约束：
- **战力来源**：进攻星芒数量/强度 + 防守建筑血量，均由 `game_profiles.json` 的建筑等级算得（等级来自真实行为）。
- **胜负不产生星辉/建筑经验**，只改 `arena_ratings.json` 的 Elo/段位 + 小额声望。Elo 结算走 `settleGameAction` 的声望通道，不走星辉通道。
- **服务端判定**：攻防结算在服务端用确定性算法（含 `replaySeed`），客户端只播放回放，防作弊。
- **绝不读/写 `scores.json`**。擂台结果不进评分主体。

### 16.5 结算器（统一入口）

新增一个 `settleGameAction(agentEngine, { memberId, source, dimension, amount, credential, credentialTier, ts })` 工具函数，**所有资源入账都走这里**，内部做：
1. **凭证分级校验**（§11.2）：入账金额 ≥ +20 必须 `credentialTier` 为 T2/T3；T2 需对方已确认，T3 需 AI 初审通过（未过公示期被质疑则冻结回滚）。T1 自报只允许小额。
2. **上限 + 衰减**：每日星辉总上限（默认 200）、同类行为衰减（100%→50%→25%）。
3. **短板加速**（§11.3）：若 `dimension` 属于该成员的落后维度，奖励 ×1.2。
4. **幂等**：同 source + 同 credential 不重复发奖。
5. **写账**：追加 `game_ledger.json`（含 credentialTier，审计透明），更新 `game_profiles.json`（星辉/建筑经验/声望）。
6. **触发报告**：调用 `dailyReport.generateReport` + `push` 通知到账。

### 16.6 反哺链路接口串联（AI 教练）

在 `agent` 的 PromptBuilder 里把「建议→落地」的能力接上：AI 生成建议时，若触发「建议即任务」，依次调用现有工具：
1. `data_query`（读短板）→ 2. `schedule_create`（落成日程）或新增的 `delegation_publish`（落成委托）→ 3. `notify_member` / push 提醒。

这样"看到短板 → 变成可执行的日程/委托 → 推送"在 AI 内部一条链走完，前端**只需展示**，无需新造 AI 逻辑。

**AI 审核（T3 凭证）**：新增 `verify_experience` 工具（或复用 agent 内嵌逻辑）——输入经历/证书描述 + 图片，AI 做 OCR + 与 `rank_scores.json`/`experiences.json` 交叉验证 + 矛盾检测，输出 `pass / suspicious` 及理由。`pass` 直接入账并进入 48h 公示；`suspicious` 转管理员人工；被质疑则冻结回滚。

接口：`GET /api/rewards`（列表）→ `POST /api/rewards/:id/redeem`（扣星辉，生成凭证）→ 管理员端 `POST /api/rewards/admin/:redemptionId/fulfill`。

### 16.9 虚实结合：拍卖行 + 班级攻防战（§6.5 旗舰能力一/二）

**① `game_auctions.json` —— 星辉拍卖行**

```jsonc
{
  "auctionId": "au_...",
  "title": "值日任务包（轻松岗）",
  "type": "duty_pack",              // duty_pack / decision_ticket / praise_slot / duty_order ...
  "class": "一班",                   // 拍卖范围（默认单班；管理员可设跨班）
  "startPrice": 600,
  "bids": [                         // 公开竞价记录（公示 = 防赖账）
    { "memberId": "1001", "amount": 620, "at": "beijingISO" },
    { "memberId": "1002", "amount": 750, "at": "beijingISO" }
  ],
  "status": "open",                 // open → sold → redeemed
  "winnerId": "1002",
  "redeemedAt": null,
  "createdBy": "admin"
}
```

- 接口：`GET /api/auctions?class=`（列表）→ `POST /api/auctions/:id/bid`（竞价，扣住星辉按出价冻结）→ 管理员 `POST /api/auctions`（发布拍品）→ `POST /api/auctions/:id/redeem`（兑现标记）。
- 所有竞价**公开留痕**（不匿名，防机器人刷价）；落锤时冻结价差退还。
- 复用 `settleGameAction` 星辉通道做冻结/扣款/退还，账本可审计。

**② `class_wars.json` —— 班级攻防战**

```jsonc
{
  "warId": "cw_...",
  "week": 3, "semesterId": 4,
  "sides": [
    { "class": "一班", "territory": { "totalHP": 820 }, "captain": "1001" },
    { "class": "二班", "territory": { "totalHP": 770 }, "captain": "1002" }
  ],
  "phase": "battle",                // rally(集结) → battle(对攻) → settled
  "events": [],                     // 攻防事件流（复用 §16.4 arena 的确定性结算引擎）
  "result": null,                   // { winnerClass, earnedReward }
  "createdAt": "beijingISO"
}
```

- 阵营直接取 `members.json` 的 `class` 字段，无须新增组织数据。
- 攻防结算**复用 §16.4 的确定性算法**（服务端判定 + 回放种子），班级领地 = 全班建筑聚合血量。
- 胜负奖励走 §9.2 拍卖行专属拍品（赢班解锁），不直接发星辉（防假赛——全班串通互刷没有收益，因为奖励是现实拍品而非游戏数值）。

**③ 现实事件副本（§6.5 旗舰能力三）**：复用现有 `config.json` 的学期/周次日历 + `scheduleStore`，管理员标记"体测周/考试周/运动会"事件 → 系统按日历自动解锁对应限时副本。无需新文件，副本配置写入 `game_profiles.json` 的 `events` 字段。
